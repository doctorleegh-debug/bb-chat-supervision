# 상담 품질 감독 대시보드

프레임워크와 외부 폰트 없는 한국어 정적 집계 화면입니다. 로컬 시스템 폰트만 사용하며 네트워크 API, 분석 도구, 쿠키, localStorage를 사용하지 않습니다. 자동 갱신이나 실제 상담 수집 기능은 없습니다. 워크북은 하나이며 국가 분류는 그 안의 운영 탭 기준입니다.

## 파일과 책임

- `index.html`: 접근성 구조, 개인정보·판정 정책, 로컬 자산 로딩. `data.js`를 `app.js`보다 먼저 `defer` 로드합니다.
- `styles.css`: 오프화이트, 저채도 퍼플·틸 스타일. 640/900/1200px 대응, 인쇄, 동작 줄이기 지원.
- `app.js`: 데이터 검증과 텍스트 기반 안전한 DOM 렌더링. 외부 요청 없음.
- `data.js`: **별도 데이터 담당자가 생성·관리합니다. 이 구현은 해당 파일을 생성하거나 수정하지 않습니다.**

`data.js`가 없거나 잘못된 경우 집계 대기와 안내를 표시합니다. 비어 있는 데이터에 실적·적절 판정을 만들어 넣지 않습니다. JavaScript 비활성 시 별도 안내가 표시됩니다.

## 데이터 계약

인접한 `data.js`에서 `window.SUPERVISION_DATA`를 동기적으로 설정하세요. `fetch`나 별도 JSON 요청은 하지 않습니다. 기본 빈 계약은 아래와 같습니다. 이것은 실제 집계 예시가 아닙니다.

```js
window.SUPERVISION_DATA = {
  meta: {
    title: '상담 품질 감독',
    updatedAt: null,
    timeZone: 'Asia/Seoul',
    sheetUrl: '',
    schedule: { weekday: '18:00', weekend: '16:00' }
  },
  days: []
};
```

일별 객체의 필드:

| 필드 | 계약 |
| --- | --- |
| `date` | 실제 KST 조회일 `YYYY-MM-DD`. 유효하고 고유한 날짜만 허용. |
| `cutoffAt` | 해당 검토의 실제 마감 시각. 오프셋 있는 ISO 8601 권장. |
| `status` | `completed` 또는 `partial`. 미검토·누락·실행 실패가 있으면 `partial`. |
| `eligibleRooms` | 제외 기준 적용 후 검토 대상 상담방 수. 고유 기준은 상류에서 고정. |
| `messageCount` | 마감 이전 범위의 전체 메시지 수. |
| `customerMessages`, `staffMessages`, `autoMessages` | 고객, 직원, 자동응답을 구분한 수. 자동응답은 직원 응답에 포함하지 않음. |
| `verdicts` | `appropriate`, `confirmedError`, `suspectedError`, `missingAnswer`, `sourceConflict`, `needsVerification` 숫자 키. |
| `countries` | `{code, name, rooms, messages, verdicts}` 배열. `KR`, `JP`, `TH`, `CN`, `TW`, `ZZ` 운영 탭. |
| `issues` | `{category, severity, status, summary, count}` 배열. 비식별 분류·건수만. `summary`는 렌더링하지 않음. |
| `coverage` | `candidateRooms`, `reviewedRooms`, `excludedUnread`, `excludedWaiting`, `excludedAfterCutoff`, `uninspectedAttachments`, `notes:[]`. |

숫자는 유한한 0 이상의 정수로 생성하세요. 누락·음수·문자열·비정상 숫자는 화면에서 0으로 처리합니다. 이 보정은 검증 완료를 뜻하지 않습니다. 소수는 내림 처리합니다. 상류에서는 실제 0과 미확인을 구분하고 미확인이 있으면 부분 집계로 게시해야 합니다. 숫자로 완료 상태를 추정하지 않으며 알 수 없는 상태는 확인 필요로 표시합니다. `completed`는 게시자가 선언한 상태이지 브라우저가 검토를 검증했다는 뜻이 아닙니다.

날짜는 최신순으로 표시하고 최신 게시일을 기본 선택합니다. 데이터가 없는 중간 날짜를 선택하면 빈 상태로 표시합니다. 이전·다음 버튼은 게시된 날짜 사이를 이동합니다. 중복 날짜는 입력 배열의 첫 기록만 표시하고 경고합니다. 잘못된 날짜는 제외합니다. 과거 날짜 갱신 시 중복 추가하지 말고 기존 객체를 대체하세요.

### 시각

- 모든 시각은 `Asia/Seoul`, KST (UTC+09:00)로 표시합니다. 브라우저의 현지 시간대에 의존하지 않습니다.
- `updatedAt` 및 `cutoffAt`은 `2026-10-29T18:00:00+09:00`처럼 명시적 오프셋 또는 `Z`가 있는 ISO 문자열을 사용하세요. 오프셋 없는 일시 문자열은 확인 필요로 표시합니다. 단순 `HH:mm`은 KST로 취급하지만 실제 날짜를 포함한 ISO 값이 권장됩니다.
- 평일 18:00, 주말 16:00 KST가 기본 운영 마감이며 `meta.schedule`은 표시 설정입니다. 이 화면이 예약 실행을 보장하거나 수행하지는 않습니다.
- `updatedAt`은 파일 게시 시각, `cutoffAt`은 검토 포함 범위의 마감 시각입니다. 혼용하지 마세요.

### 판정과 국가

- 발견 건수는 메시지 또는 스레드 단위의 판정 수이며 사람 수가 아닙니다. 중복될 수 있어 정확도나 고유 메시지 비율로 사용하지 않습니다.
- 누적 막대의 길이는 판정 발견 합계 기준의 시각화일 뿐입니다. 국가 막대는 해당 탭의 최댓값 기준입니다.
- `후속 검토 발견`은 의심 오류·미답변·자료충돌·확인필요의 합계이며 고유 이슈 수를 뜻하지 않습니다.
- 자료충돌·확인필요·의심 오류를 확정 오류에 합치지 않습니다. 출처의 우선순위, 버전과 적용 범위를 확인한 뒤 별도 판정합니다.
- `ZZ`는 기타·미확인입니다. 언어, 이름, 전화번호, 프로필 등으로 국적을 추정하지 않습니다. 화면의 국가 이름은 고정 운영 라벨을 사용합니다.
- 알 수 없는 국가 코드는 특정 국가나 `ZZ`로 자동 배정하지 않습니다. 동일 코드가 여러 번 있으면 집계값을 합치므로 상류는 코드별 한 행만 생성하세요.
- 전체 탭은 일별 최상위 집계를 표시합니다. 국가별 합계로 자동 대체하지 않습니다. 전체와 국가별 범위는 게시 전에 조정·검증하세요.
- 이슈 우선도는 `높음`, `보통`, `낮음`. 상태는 `대기`, `미확인`, `확인중`, `확인 중`, `검토중`, `검토 중`, `조치중`, `조치 중`, `완료`, `미조치`, `조치 완료`, `확인 필요`, `보류`만 표시하며 나머지는 상태 미분류로 표시합니다.

## 매일의 게시 절차

1. 마감 전 검토 범위를 고정하고 읽지 않음·대기·마감 이후·미검토 첨부를 집계합니다. 첨부를 열지 않았다면 검증했다고 표시하지 않습니다.
2. 승인된 근거를 확인합니다. 필요한 출처는 문서 식별자·버전·탭·셀 같은 최소 참조로 관리하고 원문 로그는 배포하지 않습니다.
3. 실제 집계를 생성하고 숫자, 날짜 중복, 국가별 범위, 직원·자동응답 분리를 확인합니다. 미완료는 반드시 `partial`입니다.
4. **파일 전체의 개인정보 검수 후** 해당 날짜 객체를 대체하고 `meta.updatedAt`을 갱신합니다. 이슈가 없다는 이유만으로 상태를 완료로 바꾸지 않습니다.
5. `data.js`는 `JSON.stringify` 등 검증된 직렬화로 생성하세요. 원문을 JS 코드로 연결하지 말고 생성 파일에 `node --check data.js`를 실행합니다. 이 파일은 코드로 실행되므로 신뢰된 생성자만 수정해야 합니다.
6. 네 정적 파일과 검수된 `data.js`를 동일한 커밋으로 게시합니다. 갱신 후 페이지를 새로 고쳐 최신 갱신 시각, 조회일, 상태와 검토 범위를 확인하세요. 캐시된 화면일 수 있으므로 화면의 갱신 시각이 기준입니다.

## GitHub Pages 배포 안내

이 구현은 배포·계정 접속·원격 저장소 변경을 수행하지 않았습니다.

- GitHub Pages에 게시하는 순간 사이트 및 정적 자산이 공개될 수 있습니다. 비공개 저장소가 사이트의 접근 제한을 뜻하지 않습니다. 이 화면에는 로그인·권한 제어가 없습니다. 내부 자료라면 승인된 인증 게이트가 있는 호스팅을 사용하세요.
- 조직 정책과 실제 Pages 접근 설정을 먼저 확인하고 집계 공개 승인을 받으세요. 소수 집단·희귀 이슈처럼 재식별될 수 있는 집계는 병합·억제하고 파일에도 넣지 마세요.
- GitHub Settings → Pages에서 승인된 배포 소스(브랜치 루트 또는 검수된 Actions 산출물)를 선택합니다. 이 폴더 내용이 게시 루트 또는 하위 디렉터리에 함께 있어야 합니다. 모든 자산 경로는 상대 경로이므로 프로젝트 Pages 하위 경로도 지원합니다.
- 공개 URL이 정해지면 빈 데이터 상태, 모바일, 국가 키보드 탐색, 날짜 이동, 부분 집계, 안전한 시트 링크를 확인하세요. 배포나 동작 검증 완료로 간주하기 전에 실제 사이트를 확인해야 합니다.
- Google 원본은 제한된 공유 상태를 유지하세요. `sheetUrl`은 인증된 사용자가 여는 HTTPS `docs.google.com/spreadsheets/d/<ID>/...`만 허용합니다. 링크의 쿼리·조각은 제거합니다. 링크를 표시해도 원본 권한은 변하지 않으며 워크북 ID 자체도 공개될 수 있습니다. 링크 공개가 승인되지 않았다면 `sheetUrl`을 비워 두세요.
- CSP는 외부 스크립트·폰트·API·프레임·폼 전송을 차단합니다. GitHub Pages가 제공하는 응답 헤더 정책을 대체하지는 않습니다. 인증, 보안 헤더 또는 API 비밀값을 정적 JS로 구현하지 마세요.

## 개인정보 금지 항목

화면뿐 아니라 **data.js, 저장소 전체, Git 기록, 배포 산출물, 콘솔, 테스트·스크린샷**에도 고객명, 연락처, 환자번호, 계정 ID, 상담방 링크, 예약 세부정보, 진료·병력·사진, 첨부파일, 원문 대화, 원문 로그, 토큰·쿠키·비밀번호를 넣지 마세요. 가명이나 해시도 재식별 위험을 없애지 않습니다.

`issues.category`와 `coverage.notes`도 실제 표시되는 문자열입니다. 승인된 비식별 분류·운영 범위 메모만 넣어야 합니다. 화면의 텍스트 렌더링은 HTML 삽입을 막지만 개인정보를 자동으로 탐지·제거하지 않습니다. `summary`는 표시하지 않더라도 원본 정적 파일에서 읽을 수 있으므로 비우거나 비식별 집계 설명만 넣으세요. 출처 참조는 제한된 원본에서 관리하며 이 대시보드에는 원문 로그를 넣지 않습니다.

## 로컬 확인

```sh
cd /path/to/dashboard
node --check app.js
# data.js 생성 후
node --check data.js
```

브라우저 검수가 필요하다면 승인된 로컬 정적 서버에서 확인하세요. `file://`에서는 브라우저의 로컬 파일·CSP 동작 차이가 있을 수 있습니다. 별도 라이브러리 설치나 외부 요청은 필요하지 않습니다. 이번 구현의 Node 구문·DOM 모의 검사는 실제 브라우저의 레이아웃/스크린리더 테스트나 실제 배포 검증을 대신하지 않습니다.
